마크다운 비교 편집기 - 작동방법
================================

1. 이 프로그램은?
- 원문(예: 5판)과 수정본(예: 6판 초안)을 항목별로 나란히 비교하면서 편집하고, 저장할 때마다 버전(수정이력)을
  남기는 웹 프로그램입니다. 마크다운을 가져오면 제목(#)별 "항목"으로 나뉘고, 표·그림·참고문헌·코멘트·자료실을 지원합니다.
- 서버가 없습니다. 브라우저만으로 동작하며 GitHub Pages에 올리면 그대로 실행됩니다.
- 데이터는 사용 중인 브라우저의 IndexedDB(용량 넉넉함)에 저장됩니다. 공유/백업은 JSON 파일 또는 GitHub 저장소 커밋으로 합니다.

2. GitHub에서 실행하기 (GitHub Pages)
1) GitHub에 새 저장소를 만들고 이 폴더의 모든 파일(.github 폴더, .nojekyll 포함)을 main 브랜치에 올립니다.
2) 저장소 Settings > Pages > Build and deployment > Source 를 "GitHub Actions" 로 선택합니다.
3) push 하면 Actions(Deploy to GitHub Pages)가 자동 배포합니다. 주소: https://<사용자>.github.io/<저장소>/
4) 내 PC에서 시험: 폴더에서 `python -m http.server 8000` 실행 후 http://localhost:8000 접속
   (IndexedDB 와 fetch 때문에 index.html 을 더블클릭하는 file:// 방식보다 로컬 서버 방식을 권장합니다.)
5) 문서를 저장소에 넣어 배포하려면: 편집기에서 [설정 > GitHub에 커밋 저장]을 하거나, [백업·내보내기 > JSON]으로 받은 파일을
   저장소의 data/document.json 으로 올리세요. 브라우저에 데이터가 없는 방문자는 이 파일을 자동으로 불러와 읽을 수 있습니다.

3. 화면 구성
- 상단: 목차 열기/닫기 | 전체 변경대비표 | 표·그림 도구 | 자료실 | 가져오기 | 엑셀 내보내기 | 백업·내보내기 | 설정 | 편집 로그인
- 좌측 목차: 파트/장/절 트리, 검색(제목+본문), 파트 선택, 필터(전체 / 변경 / 변경 없음 / 편집됨), 모두 접기/펼치기,
  항목 색 점(상태), "편집"/"새 항목" 표시, 하단 JSON 내려받기·삭제한 항목
- 본문: 경로, 제목+상태 배지, [원문 보기 | 편집하기], 저장 상태(vN), [저장 이력], [변경 저장]
  전체 비교 / 원문 / 수정 초안 / 변경추적 탭, 검토 메모·기존 수정사유, 섹션 코멘트, 이전·다음 항목 이동

4. 시작하기 (처음 한 번)
1) [가져오기]에서 원문 마크다운(.md)을 고릅니다. 수정본 마크다운도 함께 고르면 같은 제목끼리 맞춰서 비교합니다.
   - # 1단계 제목 = 파트, ## 2단계 = 장, 그 아래 = 절. 하위가 있는 제목은 본문이 있을 때만 "도입문"으로 보관됩니다.
   - 수정본에 없는 제목은 "비교 자료 없음" 상태가 됩니다. 원문과 수정본이 같으면 "변경 없음"으로 시작합니다.
   - 이전에 내보낸 JSON 백업도 같은 창에서 복원합니다. 빠르게 써 보려면 [샘플 문서]를 누르세요.
2) [편집 로그인]을 누르고 비밀번호를 입력합니다. 처음에는 입력한 값이 편집 비밀번호로 설정됩니다.
   - 보기·비교·검색·내보내기는 로그인 없이 됩니다. 편집·저장·삭제·코멘트·자료실은 로그인이 필요합니다.
   - 주의: 정적 사이트의 비밀번호는 브라우저 안의 "편집 잠금"일 뿐, 서버 보안이 아닙니다. 비공개가 필요한 문서는
     비공개 저장소/사설 호스팅을 쓰세요. (비밀번호는 [설정]에서 변경)

5. 비교 보기
- 전체 비교: 원문 | 수정 초안 | 변경추적 3열. 탭으로 한 열만 크게 볼 수도 있습니다.
- 변경추적: 문단·목록·표 행 단위로 비교하며 추가(파랑), 삭제(빨강+취소선), 수정(단어 단위 표시)을 구분합니다.
  "변경만 보기"를 체크하면 바뀐 블록만 보입니다. 목록 번호·띄어쓰기·서식만 다른 곳은 변경에서 제외하고 안내합니다.
- "변경대비표 보기" 링크 또는 상단 [전체 변경대비표]: 모든 항목을 한 페이지에서 보고 검색/필터, 인쇄, 단일 HTML 파일로 저장합니다.

6. 편집
- [편집하기]를 누르면 수정 초안과 검토 메모가 서식 있는 편집창으로 바뀝니다. 원문은 읽기 전용입니다.
- 서식: 굵게, 기울임, 위첨자, 아래첨자, 글머리 목록, 서식 지우기. 붙여넣기는 글자만 들어갑니다.
- 변경 상태: 내용 변경 / 변경 없음 / 문구 정비 / 확인 필요 / 비교 자료 없음. 변경 없음 항목을 고치면 자동으로 "내용 변경"이 됩니다.
- 항목 제목 수정, 항목 삭제(휴지통 보관), 도입문 작성(하위가 있는 파트/장에서).
- 새 항목: 목차 위 [새 항목] > 파트·장·제목 선택.
- 저장: [변경 저장] 또는 Ctrl+S(⌘S). 저장하지 않고 이동/닫으면 확인 창이 뜹니다.

7. 표·그림 삽입
- 상단 [표·그림 도구](assets.html): 보관함에 자료를 만듭니다.
  표(행·열 지정 또는 엑셀/CSV 붙여넣기), 그림(이미지 업로드, 자동 축소), 그림·도식/서식/수식(직접 입력)
  자료마다 판(5/6), 번호, 버전(저장할 때마다 새 버전)이 있습니다.
- 편집기에서 본문 위치를 클릭 > [표·그림 불러오기]: 검색/판 필터/버전 선택/미리보기 후 [본문에 삽입].
  본문의 표·그림을 클릭해 선택하면 [선택한 표·그림 교체]로 다른 버전으로 바꿀 수 있습니다.
  본문 위쪽에 "사용 중인 자료"와 "새 버전 있음" 링크가 표시됩니다.

8. 참고문헌(인용번호)
- 본문의 [1], [2-4], [3, 5] 같은 번호에 마우스를 올리거나 클릭하면 참고문헌 내용이 말풍선으로 나옵니다(원문=원문 목록, 수정본=수정본 목록 기준).
- [참고문헌 삽입]: 원문/수정본 목록에서 검색해 여러 건을 체크 > 커서 위치에 [1, 3] 형태로 삽입. 수정본 쪽은 [새 참고문헌 등록]으로 추가할 수 있습니다.
- 참고문헌 목록은 [설정]에 한 줄에 하나씩 붙여 넣으면 순서대로 번호가 붙습니다.

9. 버전 / 수정이력
- [변경 저장]을 누를 때마다 v1, v2... 로 기록됩니다(내용 변경이 없으면 기록 안 함). 처음 가져온 상태는 v0(초기 자료).
- [저장 이력]: 버전을 클릭하면 그 시점의 원문 | 수정 초안 | 검토 메모를 보여주고 [이 버전으로 복원]을 지원합니다.
  복원해도 이력은 지워지지 않고 새 버전으로 쌓입니다. 삭제도 이력이며 [삭제한 항목]에서 되살립니다.
- 다른 탭에서 먼저 저장해 버전이 어긋나면 "저장 충돌" 안내가 뜨고 내 수정은 화면에 유지됩니다.

10. 코멘트 / 자료실
- 섹션 코멘트(로그인 필요): 작성자 + 5,000자 코멘트 등록·삭제. 등록 전 입력은 항목별로 임시 보관됩니다.
- 자료실(로그인 필요): 파일(최대 100MB)을 이 브라우저에 보관/다운로드/삭제. [GitHub에 올리기]는 저장소 files/ 폴더에 커밋합니다(25MB 이하, GitHub 설정 필요).

11. 내보내기 / 백업 / GitHub 동기화
- 엑셀 내보내기: 항목별 원문·수정본·검토 메모·추가/삭제/수정 건수가 담긴 .xlsx (오프라인이면 CSV로 대체 저장)
- 백업·내보내기: 전체 JSON(이력·코멘트·자료·참고문헌 포함, 비밀번호 제외), 수정본/원문 전체 마크다운, 전체 비교표
- [설정 > GitHub]: 저장소(user/repo), 브랜치, 파일 경로(기본 data/document.json), 토큰 입력 후
  [GitHub에 커밋 저장] / [GitHub에서 불러오기]. 토큰은 GitHub Settings > Developer settings > Fine-grained tokens 에서
  해당 저장소의 Contents: Read and write 권한으로 발급하며, 이 브라우저에만 저장됩니다(공용 PC 주의).
- 팀 공유 방법: 한 사람이 편집 후 [커밋 저장] > 다른 사람은 [불러오기]. 실시간 동시편집은 지원하지 않습니다.

12. 한계와 주의
- 데이터는 브라우저별로 따로 저장됩니다. 브라우저 데이터 삭제 시 사라지므로 JSON/GitHub로 자주 백업하세요.
- 코멘트·편집 권한·자료실은 서버가 없어 "내 브라우저 + GitHub 파일" 단위로 동작합니다.
- 원본 사이트(수혈가이드라인 원문 편집기)는 서버/DB 기반입니다. 이 프로그램은 그 구조를 분석해 같은 화면·기능으로
  재구성한 별도 구현이며, 분석 내용은 원본분석.txt 에 정리했습니다.

13. 파일 구성
- index.html / app.js / style.css : 편집기 화면과 동작
- store.js : 데이터 계층(IndexedDB, 변경추적 diff, HTML 정리, 마크다운 변환, GitHub 동기화) - 원본의 서버 API 역할
- comments.js / citations.js / library.js / asset-picker.js : 코멘트 / 참고문헌 / 자료실 / 표·그림 선택
- comparisons.html(.js) : 전체 변경대비표,  assets.html(.js) : 표·그림 도구
- .github/workflows/pages.yml : GitHub Pages 자동 배포,  .nojekyll
